# 从小到大的真实验收

## 先验证控制平面

运行unittest，不需要GPU。测试fixture只检验文件格式，不是模型效果。启动界面，未装后端时计划应明确阻断；未知架构、缺分片、错误数据都不能启动。

## 第一站 真实小模型与本机

用有许可的完整小参数文本模型，例如Qwen2.5-0.5B/1.5B的高精度包。保存来源与revision。Mac运行MLX基线，执行同样提示，再做MLX4量化；不要同时改变模板和生成预算。查看文件/内存/输出/速度，记录失败也保留。

## 第二站 单张云GPU

固定云镜像、Python环境、模型和数据哈希。先SFT LoRA 20步，再CPT少量步，观察loss是否有限、checkpoint是否可加载；然后DPO、数学GRPO。几步训练只验证执行链，不证明模型效果改善。每个任务分别建环境与制品，不让量化覆盖原权重。

推理分别启用vLLM与SGLang；相同任务集，按单用户、混合长度、重复前缀、并发逐步测试。先做20条以上才讨论p95；高并发最终必须补固定到达率工具，不把本项目闭环探针当完整压测平台。

## 第三站 单节点多卡

确认GPU型号、实际总/空闲显存、NVLink/PCIe连接。训练先小模型torchrun验证rank与数据分配，再上大模型。检查只有预期进程、无重复输出冲突；停止任务后所有子进程退出。推理验证TP合法性与真实通信成本。

## 第四站 MoE 与多模态

不是仅修改model path：需要processor媒体token统计、专家参数布局、后端适配、奖励函数、质量任务和资源账本。当前只允许审计过的候选，未适配的音视频生成管线与PPO会阻断。加入专用适配器后，先做最小真实样本，再长视频/长音频/多图极限。

## 第五站 集群与生产发布

多机编排、故障恢复、凭据管理、配额、安全隔离和真实网络性能尚未实现，不能在当前版本宣称生产认证。每个通过的组合提交：模型revision、后端版本/镜像digest、硬件拓扑、命令与数据指纹、峰值资源、质量、延迟/吞吐、失败恢复日志。

## 判定不通过

能输出文字但模板错；量化破坏工具JSON；实际加载回退到高精度；GPU利用率高但吞吐低；超过服务延迟目标；取消后残留进程；训练日志含NaN；checkpoint不可恢复。任一项都不能用较小文件或较高峰值吞吐抵消。
