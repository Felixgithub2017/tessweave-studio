# 本机与远程 GPU：切换的是整个执行工作区

所有页面上方显示 `LOCAL / 本机` 或 `REMOTE GPU / 远程 GPU`、实际 hostname 和执行范围。下拉框列出当前主机已建立的 SSH 云端工作区。

## 如何使用

1. 本机打开 Studio，进入「主机与环境」。填已有 SSH config 别名、远端工作区目录、本地隧道端口、远端端口。
2. 预览命令，确认后建立工作区。只上传 Studio 代码，不传本机模型/数据/凭据；远端控制服务仅监听 loopback，由 SSH 转发。
3. 等隧道任务运行后，在顶部点击刷新，选择云端主机，确认切换。尚未就绪的连接不可选择。
4. 页面在当前标签进入云端工作区，顶部应明确显示 `REMOTE GPU` 和服务器 hostname。此后模型目录选择器浏览服务器；下载写入服务器；环境检测/安装、训练、推理和评估都由服务器执行。
5. 返回本机用顶部「切回本机工作区」。未保存表单清空；已经开始的任务不会随切换停止。

本地与远端必须使用不同的本地监听端口，例如本机8765、云端隧道8876。服务器上已有权重时，工作区授权根目录必须包含模型路径。典型租卡目录为 `/root/autodl-tmp/...`；「数据盘」不代表删除实例后永久保留，释放实例前应确认服务商的磁盘保留规则并备份。

## 为什么不只在请求中加一个 host 字段

该实现沿用每台服务器自己的 Studio 控制平面。一次切换更换完整页面/API origin，清掉页面内旧计划、路径、服务列表、下载表单和定时器，浏览器会话令牌按 origin 隔离。所有模块继续访问同源 API，因此不会出现下载在云端而部署误落本机的半切换。

| 数据/操作 | 所属主机 |
|---|---|
| 扫描模型、浏览文件、下载文件 | 当前工作区服务器 |
| Python/Conda 环境和 GPU 探测 | 当前工作区服务器 |
| 训练/压缩/部署的计划与命令 | 当前工作区服务器 |
| 聊天与模型端点的调用 | 当前工作区服务器代理到其注册的服务 |
| 任务数据库、下载记录、模型库、命令日志 | 当前工作区服务器的 state 目录 |

远端 Linux 使用受管理进程和网页日志终端，不声称能弹出远端桌面终端。云端失联会报错，**不会自动回落到本机执行**。SSH 只读硬件巡检不等于切换主机。

## 安全和生命周期

- 下拉清单不返回令牌；明确选择后才读取该隧道任务的访问凭证。
- 令牌通过 URL fragment 传给目标工作区，立即移入该 origin 的 sessionStorage 并清除地址栏 fragment。返回地址只接受 loopback HTTP origin，不携带令牌。
- 切换不会搬迁已运行的作业，也不会自动结束聊天后端。需要停止时回到原主机的任务页操作。
- 停止本机隧道只关闭连接，远端 Studio 和作业可能继续运行，也可能继续计费。
- 云端已有旧版服务时拒绝假装更新成功：明确停止旧控制服务，或另选新的工作区目录及未占用的远端/隧道端口，不自动重启正在工作的服务器。
- 当前不是多租户集群控制面：无 Kubernetes 调度、远端账号权限代理或自动跨主机文件同步。

自动测试覆盖主机状态隔离、连接就绪过滤、令牌不出现在清单、非法跳转地址拒绝，以及云端 bootstrap 的本地传输回归测试。浏览器用两个独立 loopback 工作区验证了本机→远端→本机、独立会话令牌和任务列表；这是路由隔离测试，不冒称真实 SSH/GPU 训练验收。真实云端任务依旧需相应 SSH 登录和用户执行确认。
