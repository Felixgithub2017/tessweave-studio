# 模型发现、下载与结构地图

## 一条完整路径

```text
同步组织目录（只取元数据）
    ↓ 选择仓库 / revision
锁定 commit + 文件名 + 字节数 + 内容哈希
    ↓ 可选限量测速，用户选择源
选择文件 + 新目标目录 + 明确确认
    ↓ .workbench-parts 临时文件 / HTTP Range
逐文件完整校验 → 发布到目标文件名
    ↓ 下载完成
扫描 config / safetensors header → 结构地图 → 训练或推理规划
```

不把“下载完成”当作“模型可运行”：漏选 tokenizer、processor 或某个分片仍会让后端失败。下载器允许部分文件用于研究，因此它只保证**所选文件集合**完整，不保证任意勾选集合构成完整模型。

## 如何操作

1. 启动时用 `--allow-root` 授权模型父目录。下载位置属于运行工作台的服务器，不一定是浏览器所在的 Mac。
2. 打开 **00 发现与下载**，选 Hugging Face 或 HF Mirror，选择一个组织或全部预置组织，点击同步。目录保留上次同步结果、时间、来源和失败项；不是静态编写的热门模型名单。每组织最多12项，可直接输入其他仓库ID。
3. 读取文件清单。`main` 会解析成具体 commit，以后续传仍使用该 commit。查看许可和仓库模型卡；许可不明确不等于允许商用。
4. 测速按**相同 commit、相同文件哈希**比较源。每源最多读2MiB，不落盘；包括连接开销，不代表整个大文件的持续带宽。镜像可能没同步对应版本，此时单独报告失败。测速不偷偷改变下载源。
5. 文件默认不勾选。可选完整仓库，也可先用 safetensors 筛选。审查 ONNX、GGUF、不同精度变体，避免下载几份同一个模型。优先筛选不是依赖解析器；特别是 Diffusers 多组件，应检查每个目录。
6. 输入绝对路径：父目录已存在且在授权根中，目标是**尚不存在的新目录**。确认后才开始网络下载。不会覆盖用户已有模型文件。
7. 查看文件名、已下载字节、总量、速度、状态。暂停保留 `.workbench-parts`；继续或重启后恢复时会验证已完成文件。若服务器忽略 Range，会安全重下该文件，不把完整响应拼到残缺文件后面。
8. 切换源续传时仍核对固定 commit 和每个所选文件的大小、内容哈希。无法证明是相同版本则拒绝。校验失败的完整临时文件保留为 `.invalid-*`，需自行审查清理，不会冒充完成文件。

队列当前每次只运行一个任务、每次一个文件。网络失败显示 failed，点击继续可重试；没有无限自动重试、后台守护进程、Xet 分块去重或多连接带宽聚合。暂停会等待正在阻塞的网络读（20秒超时）；校验也可以被暂停。重启后不会未经确认自行下载。

### 下载源边界

- 已实现：Hugging Face 公开模型与 HF Mirror 的 HF 兼容 API/resolve 文件下载。
- 已接入 ModelScope 原生目录、文件列表、按文件 Revision 下载与 SHA-256 校验。`main` 映射为魔搭 `master`；清单指纹不是 HF commit。魔搭与 HF 不允许交叉续传；组织目录默认排序、每页12项，本页关键词过滤，不冒充全站搜索。
- 未实现：任意 URL 下载、登录态、私有/gated 仓库。遇到授权要求不会尝试绕过，也不会把 HF 令牌发给镜像。
- 镜像不是官方安全认证：校验保证与所选源清单一致，不是发布者数字签名。默认官方元数据、之后换源会保留官方清单；若一开始选择镜像元数据，就依赖该镜像的信任。
- 现有模型扫描不全量读取权重。下载的文件则在落盘时做完整 SHA-256（LFS）或 Git blob SHA-1 校验。

## 网络结构应该如何读

**上方结构图来自配置推断，下方清单来自实际权重。两者不是同一种证据。**

- 规格卡：层数、隐藏维度、词表、Query/KV头数、FFN宽度、专家数、每token专家数、MLA压缩维度等。配置缺失就不伪造数值，原文放在折叠区。
- 已知 Decoder 家族展示输入、Embedding、重复 Block、注意力/前馈/残差和输出主干。它不是执行 trace；特殊逐层结构、多模态连接顺序仍需源码确认。
- 未知架构和 Diffusers 不强行套 Decoder 图。展示实际权重组件、子目录、逐层清单及 pipeline配置。
- 分布条按 header 中的实际存储字节绘制；张量按名称启发式归类，无法识别的保留“其他”。逐层路径来自张量名称，不因为配置声称有80层就补出80层权重。
- 张量表可以检索和每100项翻页，展示名称、shape、dtype、元素数、存储字节，不再只看到前150项。
- 量化打包元素不是原模型参数量；共享权重可能只存一份，非训练缓冲区也可能在权重里。因此界面明确写“存储元素”，不把它包装成精确可训练参数数。

## 验证与接口依据

下载状态和清单位于 `.workbench/downloads/`；目标目录中的 `.workbench-download.json` 保存来源、commit、已校验文件清单。不要随意编辑这些文件后继续任务。

接口依据：[HF Hub API](https://huggingface.co/docs/hub/en/api)、[仓库文件与 blobs 元数据](https://huggingface.co/docs/huggingface_hub/en/package_reference/hf_api)、[HF 缓存哈希约定](https://huggingface.co/docs/hub/local-cache)。本项目使用标准 HTTPS/Range 协议实现公开文件下载，没有声称实现 `huggingface_hub` 的全部缓存/Xet能力。

开发测试包含：部分流中断后续传、进程重启恢复、源站忽略Range、错误Range、换源内容不同、哈希不符、符号链接、路径穿越、Git blob校验、未知结构不生成假计算图。协议夹具不是性能跑分。
