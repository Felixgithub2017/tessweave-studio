## 部署能力不再等同于原生核覆盖（2026-10-15，第二轮）

此前的入口把“没有本平台逐卡公式”当成“没有任何部署方案”，且要求先有参数量才显示结果。这两个条件现在分开：有解析适配器时给出容量候选；有精确仓库上游配方时给出独立硬件/精度路线；两者都没有时保留调研与验证步骤并列出缺口，不能把通用步骤计作已适配。量化检查点未取得可靠逻辑参数量时仍能看配方，但不猜参数量、不生成虚假显存峰值。

### MLA/DSA 的多卡预算

新增DeepSeek V2、V3、R1（V3结构）、V3.2，以及同布局Kimi K2、GLM MLA/DSA的解析容量规则。每rank压缩缓存为 `请求数 × (分页tokens + 1尾页) × 层数/PP × [2×(kv_lora_rank+qk_rope_head_dim)+索引字节]`。TP复制latent+RoPE，**不能再除以TP**。DSA额外索引保守计`2×index_head_dim + 4×ceil(index_head_dim/128)`字节/token/layer；这是BF16键上界代理，上游FP8布局可能更小。禁用MTP、投机和共享前缀；必须启用2048-token分块prefill，临时量含路由与专家代理，峰值仍需实测。

搜索增加跨节点TP 16/32/64/128，不再被每节点8卡和61层无法均分阻断。仍校验头数、矩阵维度整除；PP仅等层候选，EP没有自动生成。权重按总专家参数、统一位宽假设均匀分片，不是某混合精度产物的已验证布局。结果的互联、主存与启动前检查不能省略。

例：H100 80GiB预设、每节点8卡、20%预留、单请求163840 tokens、685B手填参数的DeepSeek V3，在上述分块条件下，16/8/4位假设分别搜索到32/16/8卡（4/2/1节点）；峰值约54.60/54.60/59.58GiB每卡。这不是官方最低配置、吞吐成绩或量化产物可用性认证，特别不能把4-bit估算当成现成兼容权重。

形状依据：SGLang `e00930c5489053f26d86b179cee0d087f846acbb` 的 `python/sglang/srt/mem_cache/memory_pool.py`、`index_key_cache.py`，公式独立实现，不移植执行代码。标准全注意力/滑窗保守上界扩展至InternLM、Granite、OLMo、SmolLM3、Seed-OSS、GPT-OSS、MiniMax M2、GLM4 MoE和已知文本子配置；显式head_dim优先于hidden/heads，滑窗不计回收收益。递归、混合线性和未知层类型不会因此被放行。

## Kimi Linear 混合架构与多卡规划（2026-10-15）

规划的目标是给定上下文、驻留请求数、精度和设备，搜索满足预算的卡数，而不是判断能否塞进单卡。`gpu_count=0`自动搜索；用户固定卡数时不偷偷加卡。Kimi Linear现在由专用容量适配器处理，不再套标准GQA公式或只展示权重。

来源与范围：官方[Base配置](https://huggingface.co/moonshotai/Kimi-Linear-48B-A3B-Base/blob/3b171c17bfc4ee348599b6781a2ca8715c21c8dc/config.json)有27层、20层KDA/7层MLA（层号从1开始）、32个KDA头、头维128、卷积核4、latent512/RoPE64、256专家/每token选8。上下文来自`model_max_length=1048576`，同时兼容标准`max_position_embeddings`字段；此前只读后者且界面上限1000000造成错误回退。未下载权重、未执行远程模型代码。

实现为独立公式，不复制上游代码。状态形状参考[SGLang固定commit的mamba_utils.py](https://github.com/sgl-project/sglang/blob/e00930c5489053f26d86b179cee0d087f846acbb/python/sglang/srt/configs/mamba_utils.py)中`KimiLinearStateShape`和同commit的`configs/kimi_linear.py`。注释保留来源及不变量；这不是TessWeave原生KDA/MLA内核。

每个TP rank的缓存账本（S为逐请求页对齐后的输入+最大输出，B为驻留请求数）：

- MLA：`B × S × 7 × (512+64) × 2 bytes`。压缩latent/RoPE按TP复制，**不能除以TP**；没有假装普通K/V头分片。
- KDA：`B × 20 × (32/TP) × [128²×4 + 3×128×(4−1)×2] bytes`。循环矩阵FP32、卷积历史BF16，只随驻留请求数增长，不随S增长。
- MoE：全部权重按总参数/TP驻留，不能把激活3B当作驻留3B。路由与选中专家临时张量代理为`min(BS, chunk) × [12d+4E+4topk×moe_intermediate_size]`，每卡不假定分片收益，并与手填激活预算取大值。默认chunk=2048，必须启用对应分块prefill；这不是测得峰值。
- 混合长短请求：MLA逐请求分页再求和，KDA按总驻留数计，固定权重只计一次。界面保留彩色逐卡显存图、并发表及上下文增量。

当前只搜索同节点TP且要求头数/FFN整除；PP=EP=1，不虚构多节点、PP或EP适配。没有候选时如实报告此搜索范围内未找到布局，不等同于模型无法部署。MTP、前缀状态快照/额外状态池必须关闭或另计预算；4/8位只是容量假设，不能保证有可运行量化产物。非GPU设备不继承此CUDA/TP候选。

复算样例：总参数49,122,681,728，BF16，H100铭牌80按GiB预算，每卡安全预留20%、激活8GiB、工作区4GiB：

| 上下文/请求 | 驻留请求 | 自动候选 | 每卡峰值代理 |
|---|---:|---|---:|
| 4096 | 1 | 2卡 TP2 | 57.800 GiB |
| 1048576 | 1 | 4卡 TP4 | 42.760 GiB |
| 1048576 | 4 | 8卡 TP8 | 54.957 GiB |

卡数离散变化来自TP整除约束和逐卡缓存复制；不是负载变大却反而更省总显存。4卡TP4在1M长度的本预算内存上限是3路，不是满足延迟的业务并发保证。

部署验收：固定上述模型revision及兼容vLLM/SGLang版本→配置候选TP、上下文、并发、分块prefill→关闭未计入功能→测加载/prefill/decode/Graph逐卡峰值→对照质量与TTFT/ITL→再开放服务。官方模型卡的Instruct示例不能作为Base在所有设备上的实机认证。不自动安装、下载或启动。

验证：新增4项测试覆盖自动多卡、1M别名、混合请求、状态公式、MLA复制、分页及非法层表拒绝；完整216项测试通过。浏览器真实调用本地规划接口，选择Kimi fixture后自动带入1M并出现TP4与彩色显存图；无执行请求。均为CPU/浏览器验证，不是GPU验证。该适配器位于Studio的`hybrid_cache.py`，尚未接入独立Engine离线CLI；两者不可混称已统一支持。

### 并发与混合长度口径

彩色图按驻留序列数B（默认1）×每请求上下文S计算，S包括输入、历史和最大输出。权重共享，KV逐请求分配。固定卡数及TP/PP后给出显存并发上限，不等于满足TTFT/延迟目标的服务并发。固定GPU数量填0时为自动选卡，结果必须结合实际分配卡数阅读。

“混合长度对照”填写`2049:2,8192:1`表示两路2049 tokens和一路8192 tokens，16-token页下预留`2064×2+8192=12320`tokens。逐请求取整再求和，不能平均后取整；不计前缀共享。主图仍为等长基准，独立混合图显示固定预算、KV、激活代理和总峰值。同配比扩容上限按完整组重复求解，不是任意请求分布的最大值。标准全注意力GPU解析适配可计算；端侧混合长度暂明确提示未适配，不能把忽略该输入的等长结果当混合结果。端侧并发上限仅固定运行时预算代理。特殊结构缺适配时仍显示未知。

## 部署量化与端侧设备（2026-10-14）

部署规划主面板可直接选择16/8/4-bit权重容量假设，修改后400ms防抖重算。此选择不是对当前权重文件做量化，也不自动确定AWQ/GPTQ/GGUF/MLX/RKLLM/QNN格式；产物不可互换。4-bit另计0.0625字节/参数元数据代理，8-bit元数据尚未建模，实际混合精度保留层和加载解包峰值必须核验。KV保持BF16，不能把权重压缩倍数乘到KV上；量化质量、吞吐和芯片内核支持不由位宽推断。

新增独立端侧分支，首批8个入口：Jetson Orin Nano/NX、RK3588/RK3576、Snapdragon（需明确手机/PC SKU）、QCS6490、Atlas 200I A2、Apple Silicon（需明确M系列）。这是候选生态路线，不是已实测兼容矩阵。芯片不固定板卡RAM，用户必须填写实际可见GiB；系统/其他应用默认2GiB与运行时/激活默认1GiB仅为可修改起点。预算为`总内存×(1−预留比例)−系统预算`，占用为`权重+量化元数据+标准BF16 KV+运行时/激活预算`。不把统一/共享内存称为独占显存，不搜索多端设备TP/PP，不把NPU TOPS换算成tokens/s。容量满足仍显示“未认证”；缺少结构或特殊架构的KV与总占用显示未知。

## 用户旅程

### 模型驱动的 SFT → GRPO 连续方案（新增）

后训练向导顶部可以选择当前主机本地模型并生成连续解释。后端只读取 config 与全部 safetensors 头，返回架构事实、LoRA 目标参数预算、分阶段状态账本及数据契约，不加载权重。

方案按六个问题展开：模型内部如何计算；SFT 的目标 token 如何形成交叉熵与梯度；如何验收并交接 SFT checkpoint；GRPO 怎样用组内奖励形成策略梯度；两阶段分别需要什么硬件；如何预检、冒烟、监控和交付。每项包含理由，不只给配置数字。

必须纠正：SFT 不是 GRPO 前置硬要求；GRPO 不是通用质量增强按钮；LoRA 不是与 SFT 对立的算法；无 critic 不等于 RL 无额外内存；奖励提升不等于真实质量提升。旧采样策略与 KL 参考策略也不能混淆。

账本是条件性设计：BF16 底座／适配器、保守 FP32 梯度／主副本／Adam、独立参考模型与标准 attention rollout KV。MoE、多模态、未知架构不套用标准 KV；激活与工作区默认未知，不给虚假可行结论。输入的正值是用户预算，不是实测。

目前 LoRA 账本仅覆盖 q/k/v/o/gate/up/down 二维投影；执行器的 all-linear 可能更广，因此必须在执行前对齐，不能把局部参数量当成整条配方的精确显存。单卡容量结论不代表推荐了具体 GPU 型号或最快方案；多卡角色放置、实测吞吐和自动 checkpoint 串联仍待实施。

验证：6 项后端测试覆盖公式、缺失参数、MoE 阻断、输入校验、容量及真实 API 权重头读取且不创建任务；浏览器测试覆盖连续方案渲染和输入修改后的旧结果失效。未做 GPU 训练验证。

1. 选择当前执行主机与模型，查看模型身份、结构、模态和权重格式。
2. 告诉系统目标：学任务与格式 → SFT；已有偏好对 → DPO；可验证奖励与采样预算 → GRPO；需要价值模型的在线 RL → PPO。
3. 将训练目标与参数更新方式分开。LoRA 不消除前向与激活成本，QLoRA 不等于把所有张量都变成 4 bit。
4. 在数据页按模型／训练器生成字段指南、查看 JSONL，检查数据。教学样例不能替代生产数据审核。
5. 用资源规划器评估容量、并行和预算；偏好／RL 要分别评估策略、参考、奖励、价值、rollout，不能复用单模型 SFT 账本。
6. 扫描环境，预览命令及依赖配置方案，用户确认后执行。不得静默安装或自动开启计费任务。
7. 保留命令、响应、退出状态和配置。日志已有入口；统一 loss/reward/KL 等指标曲线和训练 checkpoint 对比尚需实现。
8. 在固定验证集验收质量，再把选定 checkpoint 交给部署规划与服务就绪检查。速度和低 loss 都不能单独证明质量。

## 推荐引擎的执行顺序

先过滤模型架构、算子、精度、OS 和运行时兼容性，再计算状态/激活/KV/工作区峰值，最后用相同质量门槛下的 TTFT、TPOT、吞吐、并发、功耗和费用做 Pareto 候选。没有实测就标记待校准，不称“最佳”或“最快”。端侧需额外验证转换、回退、热降频及内存与系统争用。

单纯 NPU TOPS 或 RT Core 数量不能用于预测 LLM token/s。理论 roofline 下界也不能替代实际服务排队、通信和算子测量。

## 尚待实施，按优先级

### 产品目标：可解释的模型工程方案，而非一个万能计算器

两种入口共用一套证据：

1. **从真实模型出发（面试／工程速答）**：精确识别模型 revision 与结构，展示参数与 dtype；先给静态状态账本，再分析激活、KV、瞬时聚合、通信与瓶颈，搜索候选拓扑。未知架构应给出部分结果及缺失项，不能强行用 dense 公式。
2. **从需求出发（行业方案）**：场景、模态、质量门槛、已有硬件、训练预算、部署设备、上下文、并发、延迟、隐私与功耗 → 兼容性过滤 → 模型候选 → 数据与训练路线 → 部署转换 → 验收。不是把排行榜第一名推荐给所有人。

本轮连续方案新增 ZeRO 对照：按 DP/TP/PP 展示 ZeRO 0–3 状态下界及代入公式。BF16 权重、FP32 梯度和 FP32 主副本/Adam 的假设下，全参数状态为 18 bytes/parameter，而不是无条件写 16；改精度、优化器或实现就必须改账本。表格不包含激活与 all-gather 峰值，也不证明 TP/PP 可执行。实际拓扑仍由现有联合规划器负责。

新增「场景选型」页及只读 API：文本、图文、座舱、机器人场景；CUDA、Mac、Qualcomm、Jetson、Rockchip、Ascend、MUSA 路线。首批仅 4 个有官方来源的模型／项目参考，不是全行业推荐库。参数未核验保留未知；标称参数的 BF16 权重下界不能当总显存。预算扣除非机时费用后除以整实例报价，只得到可负担机时，不得到训练耗时。
