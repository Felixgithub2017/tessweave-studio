# 架构与扩展契约

## 主线

用户选择权重 → 只读识别 → 确认任务与数据 → 盘点实际执行主机 → 分项估算 → 后端能力与版本检查 → 保存不可重复提交的计划 → 用户确认 → 真实进程 → 指标与产物 → 同负载验收。

“自动识别训练格式”的边界：配置能提示模型模态、tokenizer/processor及架构；不能从权重反推出用户想做SFT还是DPO、正确答案是什么。UI负责给出契约，数据检查负责验证，processor实际token预算与语义质量需要后端运行验证。

## 兼容性分层

1. **metadata-only**：识别结构/分片/格式，不执行。
2. **recipe-unverified**：有可生成的工业后端命令；仍需在目标GPU上验证。
3. **smoke-passed**：真实权重完成加载与至少一个训练/生成步骤。
4. **quality-passed**：独立质量集达到预先定义的阈值。
5. **production-qualified**：并发、故障、回滚、长时间运行、资源隔离通过。

当前项目只自动输出前两级或blocked；不会因为上游宣传支持某模型就填smoke-passed。不要把所有2026架构硬塞进一个CausalLM适配器。

## 插件需要交付什么

新增架构时，在审计分支扩展 inspection/adapters/planning 并附测试。当前注册表是Python静态集合，不提供从模型目录加载任意插件的接口。

| 扩展 | 必需内容 |
|---|---|
| 模型 | config解析、组件归属、权重共享、量化布局、数据processor契约 |
| 训练 | 后端版本、参数数组、loss mask、冻结范围、分布式启动、checkpoint恢复 |
| RL | actor/reference/critic/reward/rollout角色图；奖励、样本分组、权重同步、版本一致性 |
| 推理 | tokenizer模板、服务就绪条件、KV布局、停止条件、usage与指标语义 |
| 量化 | 源权重要求、校准、保留层、scale轴、导出格式、执行内核及质量测试 |
| 剪枝 | 结构合法性、恢复训练、实际稀疏/结构内核收益；不能只把权重置零 |
| 硬件 | 设备容量、精度能力、实际可用量、网络拓扑、集合通信证据 |

## 资源与拓扑

参数计数来自safetensors header存储元素，未量化时可作初步估计；共享参数与buffers仍可能造成偏差。量化后的整数packing、scale不能当原参数量。文件指纹只覆盖config/header/大小/mtime，**不是每个权重字节的密码学证明**；正式发布需要另做全文件哈希与不可变制品。

训练全参基础账16P只对应一种混合精度Adam约定。ZeRO-3理论分片不等于整块峰值都按卡数整除；层all-gather、激活、logits与通信池未计。MoE按总参算存储，按真实路由算运算。MLA/混合注意力不能用普通GQA KV公式。

同机TP优先高速互联；跨机PP/DP/EP选择依赖模型与网络。本版只生成单节点实际命令，跨节点仍为审计任务。要进入自动拓扑搜索，须增加：硬件能力目录版本、每个候选合法性、实测峰值、代价模型、低成本探跑、结果缓存与失败回退。

## 安全与进程

loopback + 每次启动随机令牌 + Host/Origin检查。模型/数据路径受显式根目录约束；不接受任意shell。任务由参数数组启动，stdin关闭；停止仅作用于当前控制器拥有的进程组。服务退出会请求停止任务，强制崩溃后的历史running状态标记interrupted，不冒险按历史PID杀其他进程。

浏览器终端是实际stdout/stderr查看器，不是可输入任意命令的远端shell。生产多用户版本必须替换本地HTTP控制平面：TLS/OIDC/RBAC、队列与租户配额、独立worker容器、审计、日志脱敏、指标存储、制品签名。不能把标准库开发服务器直接暴露公网。

SSH巡检只调用固定Python探针，通过系统密钥和known_hosts认证；不保存密码。远端执行目前采用“控制平面运行在云机+SSH转发”，没有伪装成已有多节点agent系统。
